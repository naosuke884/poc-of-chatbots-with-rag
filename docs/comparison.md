# 3 方式の比較

シンプルなベクトル検索・ベクトル検索 + Jev で並べ替え・PageIndex の 3 方式を、同じ資料・同じ評価セット・同じ回答生成(Claude Sonnet 5.5、同じプロンプト)で比べた結果。方式の違いは、回答生成に渡すコンテキストの集め方だけにしている。本実装の第一候補は「ベクトル検索 + Jev で並べ替え」([採用方針](report.md))。

問題ごとの結果(質問文・回答を含む)は `data/eval/` にあり、公開リポジトリのためコミットしていない。表は `uv run python -m rag_poc.compare` と `uv run python -m rag_poc.retrieval_eval --table` で出力したもの。

## 方式の構成

| | ベクトル | ベクトル + Jev で並べ替え | PageIndex |
|---|---|---|---|
| 索引 | ページをまたがない 600 文字前後のチャンク(150 文字重ね)。3 冊で 320 件 | 同左 | 資料ごとの目次ツリー(節の見出し・ページ範囲・要約)。3 冊で 81 節 |
| 索引作成のモデル | OpenAI text-embedding-3-large(3072 次元) | 同左 | Claude Haiku 5.5(PageIndex OSS 0.4.5) |
| 保存先 | PostgreSQL + pgvector | 同左 | JSON ファイル |
| 検索 | 質問の埋め込みに近いチャンクを 8 件 | 近いチャンクを 30 件取り、TypeSafe AI の Jev に「このチャンクに質問の答えが書かれているか」を判定させて上位 8 件を選び、それぞれのページ全体に広げる | 全資料のツリーを Sonnet 5.5 に渡し、読むべき節を最大 5 つ選ばせる。そのページ本文を最大 10 ページ |
| 回答生成 | Claude Sonnet 5.5(共通) | 同左 | 同左 |

- Jev は文章を書かず、yes/no などの判定を確率で返すモデル。1 回の呼び出しで 30 件のチャンクと 30 個の判定をまとめて送り、約 0.3 秒で返る
- 埋め込みは「話題が近いか」を測るので、言い回しが違うと答えのチャンクが上位に来ない。並べ替えは質問とチャンクを一緒に読ませて「答えが書かれているか」を判定するので、話題が近いだけのチャンクと見分けられる(公開日を問う q01 では、埋め込みで 14 位の正解チャンクが Jev で 1 位になった)

## 計測結果(3 冊・148 問、回答と採点まで)

評価セットは、人が作った 50 問(q01〜q50)に、LLM で作って点検した 98 問(q51〜q148、人は確認していない)を足したもの。作り方は README の「評価セット」を参照。計測は 2026-10-24。

| 指標 | ベクトル | ベクトル + Jev で並べ替え | PageIndex |
|---|---|---|---|
| 正答率(部分正解は 0.5) | 95% | 100% | 98% |
| 正解 / 部分正解 / 不正解 | 137 / 6 / 5 | 147 / 1 / 0 | 144 / 2 / 2 |
| 　事実の参照 | 93%(n=79) | 99%(n=79) | 96%(n=79) |
| 　複数箇所 | 91%(n=22) | 100%(n=22) | 100%(n=22) |
| 　数値・表 | 98%(n=26) | 100%(n=26) | 100%(n=26) |
| 　答えなし | 100%(n=21) | 100%(n=21) | 100%(n=21) |
| 　本編の問題 | 96% | 100% | 97% |
| 　付録5の問題 | 98% | 99% | 100% |
| 　付録3の問題 | 84% | 100% | 98% |
| 正解ページを検索で取得できた割合 | 93% | 100% | 97% |
| 正解ページを根拠に挙げた割合 | 92% | 99% | 97% |
| 応答時間 平均 / 中央値 / 最大 | 2.7 / 2.2 / 17.8 秒 | 3.2 / 2.8 / 8.8 秒 | 5.1 / 4.9 / 8.7 秒 |
| 　うち検索 / 生成(平均) | 0.2 / 2.4 秒 | 0.5 / 2.7 秒 | 2.8 / 2.3 秒 |
| 1 問あたりの料金 | $0.0108 | $0.0151 | $0.0255 |
| 1 問あたりのトークン 入力 / 出力 / キャッシュ | 4,728 / 146 / 0 | 21,984 / 680 / 0 | 8,536 / 320 / 26,252 |

- 採点は Claude Opus 5.5 が、正解・正解の根拠ページの本文・回答を比べて行う。1 問につき 2 回採点し、判定が食い違った問題は低いほうを採って人が見る対象にする。3 方式とも食い違った問題はなかった
- 正答率の差は最大 5 ポイント(148 問で 7 問ぶん)。同じ方式・同じ問題でも計測するたびに 1〜2 問ぶん結果が変わるので、1〜2 ポイントの差は差とみなさない
- ベクトルと PageIndex は同時に走らせ、Jev で並べ替える方式は別の時間帯に単独で走らせた。応答時間の回答生成の差(2.3〜2.7 秒)は、計測した時間帯の違いによる揺れを含む
- 料金は 1 問あたりの検索と回答生成の合計。採点の料金(2 回採点で 148 問あたり約 $2.7)は含まない。Jev で並べ替える方式のトークン数には、Jev に送った約 15,400 トークン($0.0007 ほど)を含む

## 資料を 11 冊に増やしたとき(検索だけ)

3 冊・148 問では正答率が 95〜100% に集まり差が出にくかったため、似た記述の多い資料を足して検索の精度を比べた。足したのは同じガイドラインの付録・説明資料のうち PDF で配布されている 8 冊(付録 1・7・8、自社診断 解説編、6 か条 解説編、説明資料 3 冊)で、合計 388 ページ。回答生成と採点はせず、検索だけを流して正解ページを取得できたかを測った(`rag_poc.retrieval_eval`)。計測は 2026-10-31、方式ごとに単独で走らせた。

| 方式 | 正解ページの取得 3 冊 → 11 冊 | 付録3 の問題 3 冊 → 11 冊 | 追加資料の問題(11 冊) | 渡すページ数 3 冊 → 11 冊 | 検索の時間 3 冊 → 11 冊 | 検索の料金 3 冊 → 11 冊 |
|---|---|---|---|---|---|---|
| ベクトル | 93% → 92% | 85% → 98% | 91% | 5.8 → 6.4 | 0.2 → 0.2 秒 | $0.00001 → $0.00001 |
| ベクトル + Jev で並べ替え | 100% → 98% | 100% → 100% | 97% | 5.8 → 6.2 | 0.5 → 0.4 秒 | $0.00065 → $0.00060 |
| PageIndex | 97% → 97% | 85% → 98% | 96% | 7.8 → 8.7 | 2.7 → 2.9 秒 | $0.00753 → $0.01853 |

- 「追加資料の問題」は、追加の 8 冊から作った 95 問(`rag_poc.evalgen_extra`。102 問を下書きし、11 冊の全文と照らした点検を 95 問が通過、人は確認していない)。それ以外の列は元の 148 問
- 正解ページは、ほかの資料に同じ答えがあるページも正解として数えた(`rag_poc.evalgold`。Opus 5.5 に、そのページだけで正解の要点がわかるページを挙げさせた)。元の 148 問のうち 42 問、追加資料の 95 問のうち 47 問に、ほかの資料にも正解のページがあった
- 元の 148 問では、資料を 2.8 倍に増やしても正解ページの取得はほとんど下がらなかった。元の正解ページだけで数えるとベクトル 93% → 86%、PageIndex 97% → 93% と下がるが、追加の資料の同じ内容のページを取るようになっただけ
- 追加資料の問題では方式の差が開いた。ベクトル 91%、PageIndex 96%、Jev で並べ替え 97%。元の正解ページだけで数えるとベクトル 85%、PageIndex 88%、Jev で並べ替え 97% で、並べ替える方式は問題を作ったページそのものを取れている
- ベクトルで落とした問題は自社診断 解説編(110 ページ)と付録 8 に多く、取ったページは同じ資料の別のページや、内容の近い資料のページに分かれていた
- PageIndex は目次ツリーが約 3 倍(7.9 万トークン)になり、検索の料金が 2.5 倍になった。ほかの 2 方式はほとんど変わらない

## 構築の手間

| | ベクトル / ベクトル + Jev | PageIndex |
|---|---|---|
| 索引作成の時間 | 4.9 秒(3 冊の埋め込み) | 約 3.5 分(3 冊、LLM の呼び出し) |
| 索引作成の料金 | $0.021 | $0.036 |
| 用意するもの | ベクトル DB(pgvector)、チャンク分割の設計。並べ替えには Jev の API | なし(ツリーは JSON で持てる) |
| 決めること | チャンクの大きさ・重ね幅・取得件数・並べ替えの候補数 | 1 回に読むページ数の上限・選ぶ節の数 |
| 前処理 | 本編の余白の縦書き見出しの除去(共通) | 同左 |

- どの方式も 1 日かからずに組めた。ベクトル系は DB の準備があり、PageIndex はツリーの中身(節の切れ目が本文と合っているか)の確認が要る
- PageIndex の索引作成は資料の構成に左右される。今回の資料はどれも見出しがはっきりしていて、目次ページのない付録 3・付録 5 でも本文から見出しを推定できた
- 資料を差し替えるとき、ベクトル系は該当資料のチャンクを入れ替えるだけで済む。PageIndex も資料ごとにツリーを作り直すだけだが、1 冊に数十秒〜数分かかる

## 誤答の傾向(3 冊・148 問)

### ベクトル

- 不正解 5 問・部分正解 6 問。多くは正解ページを取得できていないもの(公開日、付録 3 の対策例のページ、本編の脚注にある委員会の性格など)。質問と本文の言い回しが離れていると、近いチャンクの上位 8 件に入らない
- 付録 3 の問題が最も弱い(84%)。付録 3 の正解チャンクは付録 3 の中では 1 位でも、全体で並べると本編・付録 5 の似たチャンクに押されて漏れる
- チャンクだけを渡すので、表が複数のチャンクに分かれると範囲を読み違えることがある

### ベクトル + Jev で並べ替え

- 部分正解 1 問(q113)だけ。正解の 2 ページのうち 1 ページが漏れ、回答が注記を見落とした
- ほかの方式で落とした公開日(q01)・付録 3(q47・q48)・段組みの表(q75)なども正解した。q75 は 1 回の計測でのことで、表の取り出しの課題(report.md)が解けたわけではない
- 並べ替えの上限は、埋め込みで取った 30 件の候補に正解が入っているか。11 冊で、正解ページが 30 件の候補に入っていた割合は 98% だった

### PageIndex

- 不正解 2 問・部分正解 2 問。q75 は本編の表 2 が PDF から取り出すと列の対応が崩れ、どの STEP の例かを本文から読み取れなかった。q63 は付録 5 のログの保存期間の規定のページを取り、ログが自動削除されるという本編の記述のページを取らなかった
- 正解ページを取得できた問題は、ほとんど正しく答えた。節単位でページを丸ごと渡すので、表や前後の文脈が切れない
- 目次ツリー(3 冊で約 2.7 万トークン)を毎回送る。プロンプトキャッシュで料金は 1 割に下がるが、ツリーは資料が増えるほど大きくなる

### 共通

- 答えのない質問(21 問)は 3 方式とも全問「記載がない」と答えた。回答生成のプロンプトに「抜粋にない場合は答えない」と書いたのが効いている。そのぶん、答えがあるのに「記載がない」と答える側に倒れることがある
- q52(退職・契約終了時の対策)は本編の問題として作ったが、付録 5 にも近い規程があり、ベクトルと PageIndex は付録 5 にもとづいて答えた。問題の作り方の課題(対象の資料を質問に含めていない)

## 試して採らなかった方式

ほかにも次の方式を計測した。コードは消し、経緯は git の履歴と Linear に残している。

| 方式 | 結果 | 採らなかった理由 |
|---|---|---|
| ベクトル(ページ拡張): 取った 8 件をページ全体に広げる | 3 冊・148 問で正答率 97%、2.6 秒、$0.014 | 正解ページの取得はベクトルと同じ 93%。並べ替える方式の一部(ページに広げる処理)として取り込んだ |
| ベクトル(資料ごとの枠): 全体の上位 8 件に、資料ごとの上位 2 件を足す | 正答率 98%、2.6 秒、$0.018。追加資料の問題で 93% | 資料数に比例して渡すページが増える(11 冊で 21 ページ、44 冊で 79 ページ) |
| ベクトル + Haiku で並べ替え: Jev の代わりに Haiku 5.5 で 0〜10 点を付ける | 正答率 99%、正解ページの取得 100%、追加資料の問題で 98% | 精度は Jev と同じだが、並べ替えに約 4 秒かかり応答時間 6.9 秒。Jev を使えない場合の代わりになる |
| PageIndex の節の選択を Jev で行う | 正解ページの取得 83〜88%、検索 0.6 秒、$0.004 | 節の要約だけでは答えのある節を見分けられない。目次探索には LLM の推論が要る |
| ベクトルで資料を 3 冊に絞り、そのツリーで節を選び、Jev でページを絞る | 追加資料の問題で 89%、検索 3.4 秒、$0.056 | 埋め込みでの資料の絞り込みで正解の資料が漏れる(落とした 11 問中 7 問)。ツリーの組み合わせが質問ごとに変わりキャッシュも効かない |
| ベクトル + Jev の結果に PageIndex の結果を足す(保存済みの結果からの試算) | 11 冊で正解ページの取得 99% | 上積みは 100 問あたり 1〜2 問で、PageIndex の時間(約 3 秒)と、資料数に比例する料金が加わる。精度を最優先する場合の選択肢として report.md に残した |
